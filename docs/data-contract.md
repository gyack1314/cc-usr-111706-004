# 自备机组许可与运行采集资料约定

正式运行与实际发电量尚无证据。normal.json 描述两份来源，conflict.json 用同一身份和版次给出不同原文。原文、解释记录和可见状态需要一致，不能用合成资料推断现实设施或排放。

## 记录边界

- 原文按来源响应整体登记；同一响应可含多条记录（州目录常见），每条按自身身份和版次登记。
- 主要来源为许可（`generator`），关联来源为设备清单（`equipment`）和运行申报（`support`），撤回单独登记为 `withdrawal`。基线类型名保持不变，`kind` 字段给出实际类别。
- 许可编号、机组身份、设备身份、燃料、容量、适用期间和原文附件分别保留，避免同一许可的换型或撤回覆盖旧证据。
- 阶段只承认 `approved`、`installed`、`trial`、`operational`；未知阶段保持为空并进入缺口。撤回、过期是许可状态，不是阶段。
- `capacity_mw` 是当前可依据的容量；`capacity_basis` 说明来自有效许可、设备铭牌还是已撤回/过期的历史许可。`actual_generation_mwh` 只来自运行申报的实测电量，容量从不替代电量。
- 设备换型按适用期间和接收顺序追加，旧设备标记 `superseded` 并指向后继，不删除。许可撤回同样不删除许可记录。
- 附件只有在收到原文字节后才写入 `attachments`；仅有链接的附件保留为 `declared_attachments`。声明摘要与实际字节不符时整份响应回滚。
- 设施归属不足两个独立来源时保留为候选（`candidate`），多个候选时保留全部并标记 `ambiguous`，不强制归并。
- 迟到申报按已收到的顺序和适用期间标注 `late_arrival_records`，记录仍参与展示和缺口说明。同一期间有多份申报时，电量只计最新一份，原始记录全部保留。
- 撤回、过期、暂停、被拒分开：`permit_status` 取 `active`、`withdrawn`、`expired`、`suspended`、`denied`；部分许可撤回时按剩余有效许可取容量，并给出缺口说明。
- 同一响应内出现同身份同版次但内容不同的记录视为冲突，整份响应回滚。收到但无法关联的记录或附件保留为 `unlinked_receipts`，并阻止发布。
